# 双按键与单通道触摸：离线诊断

本例是独立诊断固件，不运行小智、联网、双眼绘制、音频或相机。现有屏幕可能停留旧画面或无画面，不以此判断显示硬件损坏。

## 安全接线与范围

| 功能 | GPIO | CN4 图纸 Pin | 接法 |
|---|---|---|---|
| 触摸 | 11 | 1 | 一根信号线到铜箔；不接电源/地 |
| 按键 A | 12 | 2 | 常开瞬时触点到 GND |
| 按键 B | 13 | 3 | 常开瞬时触点到 GND |
| 马达保留脚 | 14 | 4 | 只设为低电平；本轮模块 IN 和 VCC 物理断开 |
| VBAT | — | 5 | 不用于本轮测试，绝缘 |
| 地 | — | 6 | 按键共地 |

Pin 编号不是实物左右顺序。请确认实际板的 Pin 1、线序和地。禁止把 VBAT 接 GPIO。马达输入兼容性未确认前，不连接已通电模块到GPIO；这个例程没有启动马达的命令，日志中的 `MOTOR_LOCKED` 仅是程序状态，不是外部马达电压测量。

## 独立构建

在已导出 ESP-IDF 5.4.3 的环境中，从仓库根目录执行（不使用仅包含原五目标的 `tools/build.py`）：

```text
idf.py -C <仓库绝对路径>/examples/controls-test -B <仓库绝对路径>/.build/controls-test -DIDF_TARGET=esp32s3 -DSDKCONFIG=<仓库绝对路径>/.build/controls-test/sdkconfig -DSDKCONFIG_DEFAULTS=<仓库绝对路径>/examples/controls-test/sdkconfig.defaults reconfigure build
```

将所有 `<仓库绝对路径>` 替换为同一个真实路径（含空格时需按所用shell加引号）。实际生成配置必须验证为 ESP32-S3、16MB、原生 USB-Serial/JTAG 控制台。构建不代表授权刷写。

## 烧录门槛

备份并验证当前完整Flash。按当前启动日志确认活动应用分区；与本例 `partitions.csv` 和构建的 `flasher_args.json` 对照。只有分区及已有引导程序兼容，才允许仅覆盖活动应用。不要直接使用 `idf.py flash` 写入默认地址来替换已配网的小智设备。

独立回读应用的长度和SHA-256；首次启动前还需确认被保留的引导程序、分区表、OTA数据、NVS及PHY数据没有被改写。记录当前固件快照供恢复，不把本例当成新的小智版本。

## 观察步骤

原生USB串口115200。上电/真正复位后前三秒不要碰铜箔，等待 `READY base=...`。25ms按键消抖、35ms触摸状态消抖；触摸以初始固定基线为准，按下阈值约+10%、松开阈值约+5%，仅为诊断初值，不是已适配所有毛绒层/线长的最终参数。

1. 按键A（GPIO12）按下/松开三次，每次按住约1秒、松开约1秒，应看到独立 `BUTTON_A ... PRESS/RELEASE` 和计数。
2. 按键B（GPIO13）同样操作，应看到 `BUTTON_B ... PRESS/RELEASE`。
3. 触摸铜箔按住约2秒、离开约2秒，重复三次；看 `TOUCH GPIO11 ...` 事件与 `SAMPLE raw/base/delta_permille`。
4. 两键同时按下并松开，应各有自己的事件，不串键。最后不操作几秒，检查误报。

触摸没有事件但raw明显改变时，先依据数据调整阈值；不能马上判断焊线损坏。初始化时触摸、潮湿、布层/间隙、引线和电源噪声会影响基线，复位前先移开手。出现 `TOUCH_FAULT` 或valid=0不能算触摸通过。

本例不能证明马达、电池/充电、语音/显示并发或小智业务功能通过。物理按键/铜箔动作与真实串口事件对应后才记录验收。

## 恢复

恢复本轮烧录前已校验的应用受影响擦除扇区，并独立回读；如应用/分区/状态不匹配，使用本轮私有完整Flash备份和匹配流程。恢复旧四路触摸固件前继续保持震动模块断开，并断开或重新评估GPIO12/13的按键占用。完整Flash和状态日志可能含凭据，只留本地，不上传仓库。
